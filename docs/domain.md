# 领域说明

会费、赞助、工资税费和赛事报名形成不同期限的现金流，闲置余额只有在最坏情景下仍有余量时才能投资。预测假设、银行价值日、产品到期日和审批时间要分别记录。冻结资金、情景版本和回款状态属于长期留存的信息。

`reference/domain.json` 保存公开的现金事件、情景类型、告警类别和投资状态。正式记录使用稳定标识，并区分业务时间（价值日/到期日）、接收时间（recorded_at）和假设版本（version）。

## 实现约定

- 事件溯源：正式记录是 `.runtime/events.log` 中仅追加的事件；当前状态由全量重放得到，
  重启后未完成的闸门审批与风险告警继续处理。
- 情景：`base / adverse / stress`。流入按情景延后并折损，流出按情景提前，
  家长退款按情景激增。可投资上限取三情景逐日余额最低点减去冻结底线后的最小值。
- 冻结底线 = 家长退款准备金 + 管理员设定的最低现金缓冲。
- 资金闸门：新订单在各情景下模拟，击穿底线即阻断，决策快照记录触发情景（缺口最大者）、
  所有失败情景、首日缺口日期与假设版本；已批准批次的快照不可变。
- 对账幂等：银行流水以 `idempotency_key` 去重；流水与计划项两遍匹配，乱序到达安全。
  投资申购扣款与到期回款是银行账户的真实进出，以价值日为准，预测只补尚无流水的部分。
